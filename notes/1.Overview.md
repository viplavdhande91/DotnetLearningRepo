# .NET Dependency Injection (DI) – Overview


.NET provides **built-in support for Dependency Injection (DI)**.  
DI is a design pattern used to achieve **Inversion of Control (IoC)** between classes and their dependencies.

It is part of the .NET framework ecosystem along with:

- Configuration
- Logging
- Options pattern

---

# What is a Dependency?

A **dependency** is an object that another object depends on.

Example:

```csharp
public interface IMessageWriter
{
    void Write(string message);
}

public class MessageWriter : IMessageWriter
{
    public void Write(string message)
    {
        Console.WriteLine($"MessageWriter.Write: {message}");
    }
}
````

Here `MessageWriter` is a dependency that other classes might use.

---

# Problem Without Dependency Injection

Example:

```csharp
public class Worker : BackgroundService
{
    private readonly MessageWriter _messageWriter = new();

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            _messageWriter.Write($"Worker running at: {DateTimeOffset.Now}");
            await Task.Delay(1000, stoppingToken);
        }
    }
}
```

## Problems

### 1. Tight Coupling

```
Worker -> MessageWriter
```

You cannot replace `MessageWriter` easily.

---

### 2. Hard to Test

You cannot easily mock `MessageWriter`.

---

### 3. Configuration Scattered

If `MessageWriter` needs dependencies, `Worker` must create them.

---

# Solution: Dependency Injection

Dependency Injection solves these problems using:

1. Interface abstraction
2. Service registration
3. Constructor injection

---

# Step 1 — Create Interface

```csharp
public interface IMessageWriter
{
    void Write(string message);
}
```

---

# Step 2 — Implement Interface

```csharp
public class MessageWriter : IMessageWriter
{
    public void Write(string message)
    {
        Console.WriteLine(message);
    }
}
```

---

# Step 3 — Inject Dependency

```csharp
public class Worker : BackgroundService
{
    private readonly IMessageWriter _messageWriter;

    public Worker(IMessageWriter messageWriter)
    {
        _messageWriter = messageWriter;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            _messageWriter.Write($"Worker running at {DateTime.Now}");
            await Task.Delay(1000, stoppingToken);
        }
    }
}
```

Now `Worker` depends on **abstraction** instead of a concrete class.

---

# Step 4 — Register Services

Services are registered in **IServiceCollection**.

```csharp
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

HostApplicationBuilder builder = Host.CreateApplicationBuilder(args);

builder.Services.AddHostedService<Worker>();
builder.Services.AddSingleton<IMessageWriter, MessageWriter>();

IHost host = builder.Build();

host.Run();
```

---

# How DI Works

```
Service Container
      |
      |-- IMessageWriter -> MessageWriter
      |
      |-- Worker
```

When `Worker` is created:

```
DI Container
      |
Creates MessageWriter
      |
Injects into Worker constructor
```

The framework manages:

* Object creation
* Dependency resolution
* Disposal

---

# Benefits of Dependency Injection

## 1. Loose Coupling

Instead of:

```
Worker -> MessageWriter
```

We use:

```
Worker -> IMessageWriter
```

---

## 2. Easy to Replace Implementation

Example:

```csharp
builder.Services.AddSingleton<IMessageWriter, LoggingMessageWriter>();
```

No changes required in `Worker`.

---

## 3. Easier Unit Testing

Example:

```csharp
var mock = new Mock<IMessageWriter>();
var worker = new Worker(mock.Object);
```

# Example: Logging Implementation

```csharp
public class LoggingMessageWriter : IMessageWriter
{
    private readonly ILogger<LoggingMessageWriter> _logger;

    public LoggingMessageWriter(ILogger<LoggingMessageWriter> logger)
    {
        _logger = logger;
    }

    public void Write(string message)
    {
        _logger.LogInformation("Info: {Msg}", message);
    }
}
```

Register it:

```csharp
builder.Services.AddSingleton<IMessageWriter, LoggingMessageWriter>();
```

# Constructor Injection

Constructor injection is the **most common DI pattern**.

```csharp
public class ExampleService
{
    private readonly ILogger<ExampleService> _logger;

    public ExampleService(ILogger<ExampleService> logger)
    {
        _logger = logger;
    }
}
```

The DI container automatically injects `ILogger`.

---

# Constructor Selection Rules

If multiple constructors exist, DI selects:

> The constructor with the **most parameters that can be resolved**.

Example:

```csharp
public class ExampleService
{
    public ExampleService() { }

    public ExampleService(ILogger<ExampleService> logger) { }

    public ExampleService(ServiceA serviceA, ServiceB serviceB) { }
}
```

If only `ILogger` is registered, the second constructor is used.

---

# Service Lifetimes

.NET supports **three service lifetimes**.

| Lifetime  | Description                             |
| --------- | --------------------------------------- |
| Singleton | One instance for the entire application |
| Scoped    | One instance per request                |
| Transient | New instance every time requested       |

---

## Singleton

```csharp
services.AddSingleton<IMessageWriter, MessageWriter>();
```

Single instance for entire application.

---

## Scoped

```csharp
services.AddScoped<IUserService, UserService>();
```

New instance per HTTP request.

---

## Transient

```csharp
services.AddTransient<IEmailService, EmailService>();
```

New instance every time it is requested.

---

# Scoped Services in Background Services

Background services are **Singleton**, so scoped services must be created manually.

```csharp
public class Worker : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;

    public Worker(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        using var scope = _scopeFactory.CreateScope();

        var service = scope.ServiceProvider.GetRequiredService<IUserService>();

        await service.DoWork();
    }
}
```

---

# Keyed Services (Multiple Implementations)

You can register multiple implementations using **keys**.

```csharp
services.AddKeyedSingleton<IMessageWriter, MemoryMessageWriter>("memory");
services.AddKeyedSingleton<IMessageWriter, QueueMessageWriter>("queue");
```

Use a specific implementation:

```csharp
public class ExampleService
{
    public ExampleService(
        [FromKeyedServices("queue")] IMessageWriter writer)
    {
    }
}
```

# Summary

Dependency Injection enables:

* Loose coupling
* Better testing
* Flexible architecture
* Centralized dependency management

Flow:

```
Interface -> Implementation -> Registration -> Injection
```

Example:

```
IMessageWriter
      |
MessageWriter
      |
services.AddSingleton<IMessageWriter, MessageWriter>()
      |
Worker(IMessageWriter writer)

```
