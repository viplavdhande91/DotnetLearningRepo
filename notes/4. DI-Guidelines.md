# 1. Designing Services for Dependency Injection

When designing services for DI:

- Avoid static/global state
- Avoid direct instantiation of dependencies
- Keep services small and focused
- Follow **Single Responsibility Principle (SRP)**

### Avoid Static and Global State

Bad example:

```csharp
public static class LoggerService
{
    public static void Log(string message)
    {
        Console.WriteLine(message);
    }
}
````

Better approach using DI:

```csharp
public interface ILoggerService
{
    void Log(string message);
}

public class LoggerService : ILoggerService
{
    public void Log(string message)
    {
        Console.WriteLine(message);
    }
}
```

Registration:

```csharp
builder.Services.AddSingleton<ILoggerService, LoggerService>();
```

Usage:

```csharp
public class OrderService
{
    private readonly ILoggerService _logger;

    public OrderService(ILoggerService logger)
    {
        _logger = logger;
    }

    public void ProcessOrder()
    {
        _logger.Log("Order processed");
    }
}
```

# 2. Avoid Direct Instantiation

Bad example:

```csharp
public class OrderService
{
    private readonly EmailService _emailService = new EmailService();

    public void Process()
    {
        _emailService.Send();
    }
}
```

Correct approach:

```csharp
public class OrderService
{
    private readonly IEmailService _emailService;

    public OrderService(IEmailService emailService)
    {
        _emailService = emailService;
    }

    public void Process()
    {
        _emailService.Send();
    }
}
```

---

# 3. Keep Services Small

Too many dependencies indicate multiple responsibilities.

Bad example:

```csharp
public class OrderService
{
    public OrderService(
        ILoggerService logger,
        IEmailService email,
        IPaymentService payment,
        IInventoryService inventory,
        IShippingService shipping)
    {
    }
}
```

Better approach: split services.

# 4. Disposal of Services

The **DI container automatically disposes services**.

| Lifetime  | Disposal Time        |
| --------- | -------------------- |
| Transient | End of scope/request |
| Scoped    | End of request       |
| Singleton | Application shutdown |

Example disposable services:

```csharp
public class TransientDisposable : IDisposable
{
    public void Dispose()
    {
        Console.WriteLine("TransientDisposable.Dispose()");
    }
}

public class ScopedDisposable : IDisposable
{
    public void Dispose()
    {
        Console.WriteLine("ScopedDisposable.Dispose()");
    }
}

public class SingletonDisposable : IDisposable
{
    public void Dispose()
    {
        Console.WriteLine("SingletonDisposable.Dispose()");
    }
}
```

Registration:

```csharp
builder.Services.AddTransient<TransientDisposable>();
builder.Services.AddScoped<ScopedDisposable>();
builder.Services.AddSingleton<SingletonDisposable>();
```

# 5. Services Not Created by Container

If you manually create an instance, the container **does not dispose it**.

Example:

```csharp
builder.Services.AddSingleton(new ExampleService());
```

Here the developer must dispose the service.

---

# 6. IDisposable Guidelines

Do not manually dispose services resolved from the container.

Example:

```csharp
public class MyService
{
    private readonly IDisposableService _service;

    public MyService(IDisposableService service)
    {
        _service = service;
    }
}
```

The container handles disposal automatically.

# 7. Shared Instance with Limited Lifetime

Use scopes when services need shared but limited lifetime.

Example:

```csharp
public class Worker
{
    private readonly IServiceScopeFactory _scopeFactory;

    public Worker(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    public void Run()
    {
        using var scope = _scopeFactory.CreateScope();

        var service = scope.ServiceProvider.GetRequiredService<MyService>();

        service.Execute();
    }
}
```

# 8. Built-in DI Container vs Third-Party Containers

.NET includes a built-in DI container.

Use third-party containers only if advanced features are required.

Examples:

* Autofac
* DryIoc
* Grace
* LightInject
* Lamar
* Stashbox
* Simple Injector

# 9. Thread Safety

Singleton services must be **thread-safe**.

Example:

```csharp
public class CounterService
{
    private int _count = 0;

    public int Increment()
    {
        return Interlocked.Increment(ref _count);
    }
}
```

Registration:

```csharp
builder.Services.AddSingleton<CounterService>();
```

# 10. Avoid Service Locator Pattern

Bad example:

```csharp
public class OrderService
{
    private readonly IServiceProvider _provider;

    public OrderService(IServiceProvider provider)
    {
        _provider = provider;
    }

    public void Process()
    {
        var service = _provider.GetService<IEmailService>();
        service.Send();
    }
}
```

Correct approach:

```csharp
public class OrderService
{
    private readonly IEmailService _emailService;

    public OrderService(IEmailService emailService)
    {
        _emailService = emailService;
    }

    public void Process()
    {
        _emailService.Send();
    }
}
```

---

# 11. Avoid Calling BuildServiceProvider During Registration

Bad example:

```csharp
var provider = services.BuildServiceProvider();
var service = provider.GetService<MyService>();
```

Correct approach:

```csharp
services.AddSingleton<MyService>();
```

---

# 12. Avoid Static Access to Services

Bad example:

```csharp
public static IServiceProvider Provider;
```

Correct approach: use constructor injection.

---

# 13. Keep DI Factories Fast and Synchronous

Example:

```csharp
services.AddSingleton<MyService>(sp =>
{
    return new MyService();
});
```

Avoid asynchronous factory methods.

---

# 14. Captive Dependency (Lifetime Mismatch)

Occurs when a **longer lifetime service depends on a shorter lifetime service**.

Bad example:

```csharp
builder.Services.AddSingleton<Foo>();
builder.Services.AddScoped<Bar>();
```

Implementation:

```csharp
public class Foo
{
    private readonly Bar _bar;

    public Foo(Bar bar)
    {
        _bar = bar;
    }
}
```

Singleton → Scoped dependency causes incorrect behavior.

---

# 15. Scoped Service Becoming Singleton

Bad example:

```csharp
var service = serviceProvider.GetRequiredService<ScopedService>();
```

Correct approach:

```csharp
using var scope = serviceProvider.CreateScope();

var service = scope.ServiceProvider.GetRequiredService<ScopedService>();
```

---

# Summary

Key DI best practices:

* Depend on interfaces
* Avoid static/global state
* Do not manually dispose DI services
* Use correct service lifetimes
* Avoid service locator pattern
* Ensure singleton services are thread-safe
* Avoid lifetime mismatches
* Prefer constructor injection
