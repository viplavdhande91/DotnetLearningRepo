# .NET Dependency Injection — Service Lifetimes

When registering services in .NET Dependency Injection, each service must have a **lifetime**.

The lifetime determines **how long the service instance lives and how often it is created**.

.NET provides three lifetimes:

- **Transient**
- **Scoped**
- **Singleton**

---

# 1. Transient Lifetime

A **transient service** is created **every time it is requested** from the DI container.

Registration:

```csharp
builder.Services.AddTransient<IMessageService, MessageService>();
````

Implementation:

```csharp
public interface IMessageService
{
    Guid GetId();
}

public class MessageService : IMessageService
{
    private Guid _id = Guid.NewGuid();

    public Guid GetId()
    {
        return _id;
    }
}
```

Controller using the service:

```csharp
public class HomeController : Controller
{
    private readonly IMessageService _service1;
    private readonly IMessageService _service2;

    public HomeController(IMessageService service1, IMessageService service2)
    {
        _service1 = service1;
        _service2 = service2;
    }

    public IActionResult Index()
    {
        return Content($"Service1: {_service1.GetId()} \nService2: {_service2.GetId()}");
    }
}
```

Result:

Each request receives **different instances**.

Example output:

```
Service1: 3f1a1c2c
Service2: 8c9d4b7e
```

Transient services are typically used for:

* Lightweight services
* Stateless operations

---

# 2. Scoped Lifetime

A **scoped service** is created **once per request** in web applications.

Registration:

```csharp
builder.Services.AddScoped<IMessageService, MessageService>();
```

Implementation:

```csharp
public class MessageService : IMessageService
{
    private Guid _id = Guid.NewGuid();

    public Guid GetId()
    {
        return _id;
    }
}
```

Controller:

```csharp
public class HomeController : Controller
{
    private readonly IMessageService _service1;
    private readonly IMessageService _service2;

    public HomeController(IMessageService service1, IMessageService service2)
    {
        _service1 = service1;
        _service2 = service2;
    }

    public IActionResult Index()
    {
        return Content($"Service1: {_service1.GetId()} \nService2: {_service2.GetId()}");
    }
}
```

Result:

Within the same request both services are **the same instance**.

Example output:

```
Service1: 5ab2f1c3
Service2: 5ab2f1c3
```

A **new instance is created for each HTTP request**.

Scoped services are commonly used for:

* Database contexts
* Request-specific data

Example:

```csharp
builder.Services.AddDbContext<AppDbContext>();
```

`AddDbContext` registers `DbContext` as **Scoped by default**.

---

# Scoped Lifetime Rules

A scoped service should always be used **inside a scope**.

Example of creating a scope manually:

```csharp
public class Worker
{
    private readonly IServiceScopeFactory _scopeFactory;

    public Worker(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    public void Execute()
    {
        using var scope = _scopeFactory.CreateScope();

        var service = scope.ServiceProvider.GetRequiredService<IMessageService>();

        Console.WriteLine(service.GetId());
    }
}
```

---

# Invalid Lifetime Example

Injecting a **Scoped service into Singleton** directly is incorrect.

Example:

```csharp
public class SingletonService
{
    private readonly IMessageService _service;

    public SingletonService(IMessageService service)
    {
        _service = service;
    }
}
```

If `IMessageService` is scoped and `SingletonService` is singleton, this causes incorrect behavior because the scoped service becomes effectively singleton.

---

# 3. Singleton Lifetime

A **singleton service** is created **only once for the entire application**.

Registration:

```csharp
builder.Services.AddSingleton<IMessageService, MessageService>();
```

Implementation:

```csharp
public class MessageService : IMessageService
{
    private Guid _id = Guid.NewGuid();

    public Guid GetId()
    {
        return _id;
    }
}
```

Controller:

```csharp
public class HomeController : Controller
{
    private readonly IMessageService _service1;
    private readonly IMessageService _service2;

    public HomeController(IMessageService service1, IMessageService service2)
    {
        _service1 = service1;
        _service2 = service2;
    }

    public IActionResult Index()
    {
        return Content($"Service1: {_service1.GetId()} \nService2: {_service2.GetId()}");
    }
}
```

Result:

Both services always return **the same instance**.

Example output:

```
Service1: a1b2c3d4
Service2: a1b2c3d4
```

Even across multiple requests, the instance remains the same.

---

# Characteristics of Singleton Services

Singleton services:

* Created once
* Shared across the entire application
* Must be **thread-safe**
* Typically used for **stateless services**

Examples:

* Caching services
* Configuration providers
* Logging services

Singleton services are disposed **only when the application shuts down**.

---

# Lifetime Comparison

| Lifetime  | Instance Creation                      | Scope                |
| --------- | -------------------------------------- | -------------------- |
| Transient | New instance every time requested      | Short-lived          |
| Scoped    | One instance per request               | Request scope        |
| Singleton | Single instance for entire application | Application lifetime |

---

# Example Registration

```csharp
builder.Services.AddTransient<IEmailService, EmailService>();

builder.Services.AddScoped<IUserService, UserService>();

builder.Services.AddSingleton<ICacheService, CacheService>();
```

---

# Lifetime Flow Example

```
HTTP Request
     |
     |-- Scoped Service (1 instance per request)
     |
     |-- Transient Service (new instance every use)
     |
Application
     |
     |-- Singleton Service (one instance for entire app)
```

---

# Summary

Service lifetimes determine **how often services are created and how long they live**.

```
Transient → new instance every time

Scoped → one instance per request

Singleton → one instance for entire application
```
