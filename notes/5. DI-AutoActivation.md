# .NET Dependency Injection — Auto-Activation

The **Microsoft.Extensions.DependencyInjection.AutoActivation** package allows **singleton services to be created automatically at application startup** instead of waiting until the service is first requested.

Normally, DI containers create services **lazily** (only when needed).  
Auto-activation ensures that certain services are **instantiated during application startup**.

This helps reduce **latency on the first request** and allows services to **perform initialization tasks early**.

---

# When to Use Auto-Activation

Auto-activation is useful when:

- You want to **avoid slow first requests** caused by lazy initialization.
- Services need to perform **startup initialization** (e.g., cache warm-up).
- Services have **expensive constructors**.
- You want **consistent response time from application start**.

Examples:

- Cache warmers
- Connection initialization
- Startup tasks
- Preloading configuration or data

---

# Install Package

Install the package:

```bash
dotnet add package Microsoft.Extensions.DependencyInjection.AutoActivation
````

---

# Register Services for Auto-Activation

The package provides several extension methods for automatically activating services.

---

# AddActivatedSingleton

Registers a service as a **singleton and activates it during startup**.

Example:

```csharp
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();

services.AddActivatedSingleton<MyService>();

ServiceProvider provider = services.BuildServiceProvider();
```

Service implementation:

```csharp
public class MyService
{
    public MyService()
    {
        Console.WriteLine("MyService initialized at startup");
    }
}
```

Output when the application starts:

```
MyService initialized at startup
```

The service is created when `BuildServiceProvider()` is executed.

---

# ActivateSingleton

Marks an **already registered singleton** for activation at startup.

Example:

```csharp
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();

services.AddSingleton<MyService>();

services.ActivateSingleton<MyService>();

ServiceProvider provider = services.BuildServiceProvider();
```

Here:

* `MyService` is registered normally.
* `ActivateSingleton` ensures it is created during startup.

---

# TryAddActivatedSingleton

Registers the service **only if it hasn't already been registered**.

Example:

```csharp
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();

services.TryAddActivatedSingleton<MyService>();

services.TryAddActivatedSingleton<MyService>(); 
// Second call has no effect

ServiceProvider provider = services.BuildServiceProvider();
```

This ensures **duplicate registrations do not occur**.

# Complete Example

Example: **Cache warm-up during application startup**

Service implementation:

```csharp
public class CacheWarmer
{
    public CacheWarmer()
    {
        Console.WriteLine("Warming up cache at startup...");
        WarmUpCache();
    }

    private void WarmUpCache()
    {
        Console.WriteLine("Cache warmed successfully");
    }
}
```

Registration:

```csharp
var services = new ServiceCollection();

services.AddActivatedSingleton<CacheWarmer>();

var provider = services.BuildServiceProvider();
```

Output when application starts:

```
Warming up cache at startup...
Cache warmed successfully
```

# Auto-Activation with Dependencies

Auto-activated services can depend on other services through DI.

Example:

```csharp
public class StartupTaskRunner
{
    private readonly ILogger<StartupTaskRunner> _logger;

    public StartupTaskRunner(ILogger<StartupTaskRunner> logger)
    {
        _logger = logger;

        _logger.LogInformation("Running startup tasks...");

        RunTasks();
    }

    private void RunTasks()
    {
        _logger.LogInformation("Startup tasks completed.");
    }
}
```

Registration:

```csharp
builder.Services.AddActivatedSingleton<StartupTaskRunner>();
```

Here:

* `ILogger<StartupTaskRunner>` is automatically injected.
* `StartupTaskRunner` runs initialization logic during startup.

# Best Practices

### Use Only for Singleton Services

Auto-activation is intended for **singleton services only**.

Do not use it for:

* Scoped services
* Transient services

---

### Keep Startup Fast

Auto-activated services should **complete initialization quickly**.

Bad example:

```csharp
public class SlowService
{
    public SlowService()
    {
        Thread.Sleep(10000); 
    }
}
```

This delays application startup.

---

### Handle Errors Carefully

If an exception occurs in the constructor of an auto-activated service:

* The **application will fail to start**.

Example:

```csharp
public class StartupService
{
    public StartupService()
    {
        throw new Exception("Startup failed");
    }
}
```

---

### Use Hosted Services for Long Tasks

For long-running or background startup tasks, prefer `IHostedService`.

Example:

```csharp
public class StartupBackgroundService : IHostedService
{
    public Task StartAsync(CancellationToken cancellationToken)
    {
        Console.WriteLine("Background startup work started");

        return Task.CompletedTask;
    }

    public Task StopAsync(CancellationToken cancellationToken)
    {
        return Task.CompletedTask;
    }
}
```

Registration:

```csharp
builder.Services.AddHostedService<StartupBackgroundService>();
```
